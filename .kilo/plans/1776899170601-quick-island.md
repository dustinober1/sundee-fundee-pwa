# Plan: Address Site Review Feedback

## Overview

Tighten the marketing site copy, fix the accidental "meta" developer notes that leaked into production, streamline the hero CTA to reduce choice paralysis, add visual energy through accent color usage and optional lifestyle imagery, and polish the app UI mockup presentation.

---

## Tasks

### 1. Remove "Meta" Developer Notes from Production Copy

The following three components contain internal planning language that reads as placeholders or developer commentary. Rewrite each to customer-facing copy.

**`src/components/AppComparison.tsx`**
- **Current:** "The site currently promotes two products, so this section makes the split explicit instead of making visitors guess which download they should tap."
- **Rewrite direction:** Something like "Two apps, one philosophy. Pick the one that fits your training focus."

**`src/components/TrustSignals.tsx`**
- **Current:** "You do not have user testimonials yet, so this section leans on what people can verify right now: the policy surface, the distribution path, and the actual training philosophy."
- **Rewrite direction:** Something like "No hype, just transparency. Here's what you can verify before you download."
- Also consider softening the section heading "Trust comes from transparency, not fake proof." — the sentiment is good but "fake proof" is slightly aggressive.

**`src/components/ReadinessAdvisor.tsx`**
- **Current:** "This is a simple demo of the product logic. Pick the state that most matches today and get a clear training direction back immediately."
- **Rewrite direction:** Something like "Not sure what to train today? Pick how you feel and get a recommendation in seconds."

### 2. Streamline the Hero Call-to-Action

**`src/app/page.tsx`** — Hero section (around line 64)
- **Current:** Shows both "Download Sundee Fundee" and "Download Rucking Club" buttons immediately in the hero.
- **Fix:** Replace with a single primary CTA: "Explore the Apps" (smooth-scrolls to `#compare` / `<AppComparison />`). Keep both download buttons in the final download section and in the comparison cards themselves where the context exists to make an informed choice.
- Also add `id="compare"` to the `<AppComparison />` section so the anchor works.

**`src/components/AppStoreButtons.tsx`**
- Currently always renders two buttons. We can either:
  - (A) Add a `variant` prop (`"hero"` | `"footer"`) to conditionally render a single scroll-to-CTA vs. the dual buttons, or
  - (B) Inline a single `<a>`/`<button>` in the hero and leave `AppStoreButtons` unchanged for sections that need both.
- **Recommendation:** Option B — keep `AppStoreButtons` as-is for the comparison and bottom download sections; add a simple scroll-to-anchor button directly in the hero.

### 3. Inject Visual Energy

**Color Accents**
- The orange (`#f27319`) is currently used only for the download button and small eyebrow labels. Use it more deliberately to draw the eye:
  - Add a subtle orange left-border or top-border accent on key feature cards in the navy features section.
  - Use orange for hover states on blog post cards.
  - Consider an orange gradient blur behind the hero text (similar to the one behind the phone mockup) to add warmth to the beige background.

**Action / Lifestyle Imagery**
- The site currently has zero human/training photos — only app UI screenshots. The feedback specifically calls for high-quality lifestyle images of lifting or rucking.
- **Decision needed:** Do you have original lifestyle/training photos to use? If yes, we will add a new section (e.g., between Features and AppComparison) with 2–3 images and a short caption. If not, we can add a placeholder image grid component with `alt` text and `src` props ready for you to drop images into later.
- **Recommendation for plan:** Add a new `TrainingLifestyleGallery` component in `src/components/` with a responsive 2–3 image grid. Use `next/image` with `fill` and `object-cover`. If no images are available yet, populate with CSS gradient placeholders and clear comments indicating where to swap in real assets.

---

### 4. Enhance the App UI Mockup

**`src/components/HomeProductPreview.tsx`**
- The iPhone screenshots render without a device frame. The top status bar / dynamic island area appears as a solid black bar, which looks like a graphical glitch.
- **Fix options:**
  - (A) **SVG Device Frame:** Wrap the screenshot in an SVG iPhone 16 Pro frame (thin bezel, rounded corners, dynamic island pill). This is the most "premium" look. The screenshot sits inside the frame using absolute positioning.
  - (B) **Mask the top:** Use a CSS mask or rounded container to soften the top edge so the black status bar blends into the frame rather than looking jagged.
- **Recommendation:** Option A — create a lightweight inline SVG iPhone frame (or add an SVG to `public/`) and position the screenshot inside it. The existing `rounded-[2rem]` container becomes the frame background; the image itself sits inset with `rounded-[1.8rem]` to mimic the screen bezel.
