# Sundee Fundee — PWA

Recovery-aware strength training. PWA port of the iOS app at
[github.com/dustinober1/sundee-fundee](https://github.com/dustinober1/sundee-fundee).

**Stack:** Next.js 16 App Router · React 19 · TypeScript · Tailwind v4 ·
Supabase Postgres + Auth · Cloudflare Pages (target host).

---

## Quick start

```bash
npm install
cp .env.example .env.local        # fill in Supabase keys (see below)
npm run dev                       # http://localhost:3000
```

The app boots without Supabase configured — the auth proxy gracefully
no-ops and `/`, `/login`, and `/manifest.webmanifest` render. Anything
that touches the database (`/dashboard`, `/workouts`, …) needs a working
Supabase project.

## Local Supabase

```bash
npx supabase init                 # one time
npx supabase start                # spins up Postgres + GoTrue + Studio
npx supabase db reset             # apply all migrations + seeds
```

`supabase start` prints the local API URL and anon key — drop them into
`.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key from supabase start>
SUPABASE_SERVICE_ROLE_KEY=<service role key — server only>
```

Migrations live in `supabase/migrations/` and apply in order. Seed files
under `supabase/seed/` populate the exercise catalog (92 entries),
benchmark catalog (31 entries), and program template metadata (7 entries).

To run seeds against the local stack:

```bash
psql $(npx supabase status --output env | grep DB_URL | cut -d= -f2) \
  -f supabase/seed/exercises.sql \
  -f supabase/seed/benchmarks.sql \
  -f supabase/seed/programs.sql
```

## OAuth providers

Configure in the Supabase dashboard (or `supabase/config.toml` for local):

| Provider | What you need |
|---|---|
| Apple    | Apple Service ID + redirect URL (Cloudflare domain) |
| Google   | Google Cloud OAuth client + Supabase callback URL |
| Facebook | Meta app + OAuth client + Supabase callback URL |
| Email magic link | SMTP (Resend or Supabase default) |

`/login` exposes all four. The OAuth callback handler is at
`/auth/callback`.

## Acknowledged losses (web vs. iOS)

These iOS features cannot translate to the web platform and are
intentionally absent:

- HealthKit (HRV, sleep, workout import) → manual entry
- iOS Live Activities / Dynamic Island
- Home-screen widgets / App Groups
- CloudKit sync (replaced by Supabase)
- StoreKit IAP / subscription tiers (free for everyone on web)
- On-device AI generation (deferred — deterministic templates instead)

## Generating typed Supabase types (later)

The `lib/supabase/types.ts` file exposes only the `WeightUnit` /
`ExperienceLevel` / `PrimaryGoal` enums and a `UserProfileRow` interface.
Once a Supabase project exists, regenerate the full database type:

```bash
npx supabase gen types typescript --project-id <id> \
  > src/lib/supabase/database.gen.ts
```

Then re-introduce the generic on the client constructors in
`lib/supabase/{browser,server,proxy}.ts` and tighten the `as` casts in
the feature query files.
